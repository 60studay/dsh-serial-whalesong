## 三、三处病因写死（别重查）

**1.12 —— 定时/规则不认页面选的口**
`watch_loop.send_raw()` 第一行 `cfg = self.scene.cfg`，**不认** `supervisor.override_com`。
`supervisor.effective_cfg()` 只喂给"网页手动发送"那条路径。
实证：config `com=COM10`、页面选 COM7、开定时 4 秒 → 3 帧全 `rx=''`
（手动发 COM7 必回 `OK VER`，所以那 3 条是发给了 COM10）。

**1.8 —— 定时慢**
`_autosend_loop` 排期已按绝对时间表（`next_at += interval`，落后跳过，有 `skipped`/`avg_gap_ms`），
但 `send_raw` 仍走 `serial_io.transact()`：开口 → 写 → **等首字节最多 1.5 s** → 读到静默 200 ms → 关口。
**周期 = 间隔 + 一次收发耗时。** 实测 500 → 1067 ms、7 秒只发 6 次。

**1.17 —— 帧被抢**
`watch_loop.take_frames()` 是 `list(...)` + `clear()`。谁先 poll 谁拿走，其余人永远看不到。

## 七、坑（只看这几条就够）

1. **绝不能 `git add -A`**：对面可能正在同一工作区改文件。只 add 自己改的。
2. **通讯板被 gitignore**：提交里只能看到 `进度总账.md` / 交接快照 / 代码地图 / 工作流经验。
3. **PowerShell 读中文会按 GBK 解成乱码**，写文件只用 `read`/`edit`/`write` 工具。
4. **JSON 配置带 BOM**：`json.load(open(..., encoding='utf-8-sig'))`，否则 `Unexpected UTF-8 BOM`。
5. **提交消息写文件再 `git commit -F`**，别用 `-m` 塞多行中文。
6. **后台服务不要接管道**（`| Select-Object -First N` 会把服务静默杀掉）。
7. **`.py` 里别用 PowerShell heredoc**：写临时 `.py` 文件再跑。
8. `BridgeError` 用 `.kind` 不是 `.code`；HTTP 错误体是 JSON，要 `json.loads` 才能读 `error.kind`。
9. 自检的 `SKIP` 是"环境不具备"，不是失败；但**数字不可比**时要主动说明原因。
