### 已经查死的病因（别重复查）

**定时不准**：`supervisor._autosend_loop` 里 `next_at = now + interval` **之后**才调
`self.loop.send_raw()`，而 light 模式的 `send_raw` 走 `serial_io.transact()`
（开口 → 写 → **等首字节最多 1.5 s** → 读到静默 200 ms → 关口）。
**实际周期 = 间隔 + 一次收发耗时**。实测：板子秒回 500→**0.68 s**；板子不回 500→**1.65 s**。

**两个模块不能选其一**：`ports.resolve_port` 里 VID:PID 歧义在**第 1 步**就抛错，
`com` 在**第 3 步**；`supervisor.effective_cfg()` 只往 cfg 里塞 `com`、**不动 `match_*`**。
所以报错提示"去填 com"指的路**走不通**（实测两个假 CH340 证明了）。

**消息时间戳**：DSH **本来就有**（`dsh-client-ui-chat/lib/client.js` 里 `formatMessageClock`），
只是 CSS 在 `@media (hover:hover)` 里 `opacity:0`。用户消息后面还有别的用户消息时**永远不显示**。
→ 不是加功能，是覆盖样式；选择器只用 `[data-clock]`，别用带哈希的 `_1KfHza_*`。

## 五、🔴 刚查出来的 bug（未修；已并入「设置页开关」一起做）

**`serial_web` 的 `openBrowser: false` 是坏的，而且工具描述在骗 AI。**

```js
// tools/web.js:77
if (args?.openBrowser === true) argv.push('--open-browser');
// ← 没有 else，永远不会传 --no-browser
```

```python
# cli.py:658  webctl 的默认值
"--open-browser", dest="open_browser", action="store_true",
default=True   # ← 默认就是开
```

**后果**：
- 不传 `openBrowser` → 不传任何 flag → **默认 True → 浏览器照样弹出**
- `openBrowser: false` 与"不传"走同一条路 → **两个都是弹**

**更危险的是描述**：`web.js` 里写着 `Omit to just return the URL.` —— **这句是假的**。
AI 会照描述做决定，然后每次都弹用户一个窗口。

**根子在 `cli.py:658` 的 `default=True`**，不在 `web.js`。其他几层都在"老实转发"：
`cli.py:494` 传下去 → `web_service.py:164` 给子进程补 `--open-browser` → `supervisor.py:342` 弹。
**第二处独立缺陷**：`web_service.py:136-139` 复用路径也弹 —— 实例已在跑时每次 `open` 都重弹一遍。

**修法（推荐"翻默认值"，不是"补 else"）**：
1. `cli.py:658` `default=True` → **`False`**（核心 1 行）
2. `cli.py:492-493` 那段"默认打开"的注释重写（旧理由已不成立）
3. `web_service.py:133` 形参默认 `open_browser=True` → `False`
4. `tools/web.js:33` 描述改成实话："默认不弹；要弹必须显式要"
5. `tools/web.js:77` 建议补 else 显式传 `--no-browser`（防御性）

**为什么不是"只在 web.js 补 else"**：那样 `webctl` 被人工直跑时**还是弹**，CLI 默认值仍然是错的。

**验收**：不传/`false` 不弹、`true` 弹、CLI 两条路都对、实例在跑再 `open` 不弹、
`selfcheck_webctl.py` 的 `[4]` 段加 3 个断言（现只查 scene/action/mode）、
总量 287 → **290 PASS**。
**注意**：已跑的实例是旧进程，改完必须 `close` 再 `open` 才生效。
