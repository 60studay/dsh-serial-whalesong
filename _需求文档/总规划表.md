## 四、依赖图（地基优先）

用户 2026-11-09 口径："不少设计互相依赖，先把地基打好，再往上建。"

```
地基（谁都要用）
  L1 多串口并发 / 一个口一把锁
      │
      ├─→ B1 读取模式（AI 两档 + 原始流旁路）    ← 都要问"这个口现在谁在读"
      │        └─→ C1 读法卡 ─→ C2 数据计算器 ─→ C5 波形
      │                              └─→ C6 图传（最后）
      ├─→ C3 serial_wait / send_batch           ← 都要走同一把口锁
      └─→ E1 扩展包（modules/ + packs/）         ← 包也可能要碰口

旁支（不依赖地基，可随时做）
  B2 快速指令面板   C4 prompt.md 目录   E4 侧边栏 iframe   B3 外观残余

远期（依赖最大）
  L5 烧录（ISP/SWD）  ← 需要 L1 的锁 + 独立时序引擎
  L2/L3 新传输（TCP/File）← 需要 Transport 抽象（已有骨架）

## 二、统一总规划

### 批次 2.3.0 —— 「底层先稳，体验跟上」

| 代号 | 事 | 为什么这批 |
|---|---|---|
| **L1** | 多串口并发（一个口一个占用表/一把锁） | 拖到最后会挡住所有能力扩展 |
| **B1** | 读取模式：AI 两档（稳定/速度）+ 人的原始流旁路 | 每天在用，且与 L1 共用"谁在读这个口"的模型 |
| **B2** | 快速指令面板（底部一排按钮，指令存文件，AI 可 `@名字` 引用） | 成本低、每天受益 |
| **S1** | 体验期攒下的真 bug | 随时插队 |

### 批次 2.4.0 —— 「让 AI 读懂数据」

| 代号 | 事 | 依赖 |
|---|---|---|
| **C1** | 读法卡：`protocols/<场景>/decode.yaml`（字段 + 定位方式 + 类型 + 单位），工具 `serial_parse` 按卡解析；外来卡必须过"校验 → 试解析 → 标来源" | L1 之后 |
| **C2** | 数据计算器：本地算均值/峰谷/段斜率，零 token，输出带样本数与时间窗 | C1 |
| **E1** | 扩展包机制（`modules/` 能力包 + `packs/` 设备包，目录级插拔，失败隔离） | 有第一个真实包时 |

### 批次 2.5.0+ —— 「工具与外壳」

| 代号 | 事 |
|---|---|
| **C3** | `serial_wait` / `serial_send_batch` / `serial_status` 增强 |
| **C4** | `prompt.md` + `protocol.md` 目录（场景提示词） |
| **L2** | `TcpTransport` |
| **L3** | `FileChannelTransport` |
| **L4** | 网页总控界面（多场景一屏） |
| **L5** | MCU 烧录（串口 ISP + SWD）——表上最大一块 |
| **R** | 结构体检 R1 / R2（各批次之间做） |

### 最后 / 等触发

| 代号 | 事 | 等什么 |
|---|---|---|
| **E3** | AI→AI 通道 + 激活（不用用户转述） | 用户说"现在做" |
| **E4** | DSH 侧边栏 iframe（页面嵌进 DSH） | 用户说"该做了" |
| **B3** | 外观 / logo 黑白 | 已做大部分，残余等用户点 |
| **C5** | 波形可视化 | C1 之后，且真有连续数据 |
| **C6** | 图传（视频） | **最后**。⚠️ 115200 下 24fps 物理不可能（≈480 B/帧），要先换通道 |
| **L6** | CAN / SPI / I2C、流控、编码 | 按需 |
