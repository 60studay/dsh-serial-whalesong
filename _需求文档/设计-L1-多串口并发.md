# 设计：L1 多串口并发（地基）

> **状态**：设计阶段（未开工）。体验期结束后第一个动手的就是这块。
> **代号**：L1 ｜ **目标版本**：v2.3.0 ｜ **前置**：无（这就是地基）

## 一、现在到底哪里不对

一句话：**"这个口现在归谁"这件事，散在三个地方各记一份。**

| 记录 | 在哪 | 谁在读 |
|---|---|---|
| 场景状态（control / port / baud） | `logs/.runtime/state/<场景>.json` | supervisor、daemon、CLI |
| 端口持有（谁开着句柄） | supervisor 内存 + `port_held` | 网页、工具 |
| 进程级互斥 | 网页实例文件 `.web.json` | webctl、工具转发 |

**于是会出现三种真实故障**：

1. **两个场景指同一个口**，一个在发、一个在定时 → 谁也不知道对方在发（1.8 尾巴、1.31 都是这个根）
2. **定时持口期间**，AI 工具从另一个进程开同一个口 → 报"被别的程序占用"（占用者是自己）
3. **控制权按场景存** → 你在 A 交了权，AI 走 B 被拒（昨晚刚修了"同口同步"，但那是补救，不是结构）

## 二、目标（只做这三件，别扩张）

| # | 目标 | 怎么算做到 |
|---|---|---|
| G1 | **一个物理口只有一把锁**：同一时刻只有一个写入者 | 两个场景同时对该口发 `V`，序列完整、无交错、无丢字节 |
| G2 | **谁持口、为什么持，一眼可见** | `/status.port_owner` 给出 `{场景, 原因(manual|autosend|watch|tool), 起始时间}` |
| G3 | **取不到锁时给"能懂的拒绝"**，不是报"被别的程序占用" | 拒绝里带占用者与建议动作（等 / 抢 / 只读） |

## 三、方案（分三步，每步可独立验收）

### 步骤 1：把"端口锁"变成一等公民（核心）

- 新建 `PortRegistry`：以 **物理口（如 COM10）** 为键，进程内 + 跨进程两级
  - 进程内：`threading.Lock` + owner 记录
  - 跨进程：`<runtime>/locks/COM10.lock`（Windows 用 `msvcrt.locking` 或独占文件句柄）
- 所有写路径**必须**先取锁：网页发送、定时、规则触发、工具转发、CLI
- 读路径（监视、`serial_read`）也走同一注册表，但**允许多个读者**（读写分开）

### 步骤 2：把三份记录收成一份

- `state/<场景>.json` 里**删掉** `port_held` 之类的派生字段，改为**问 PortRegistry**
- 控制权仍按口同步（`4009907` 已做"同口同步"，这里改成"按口存"的正式实现：
  `state/ports/COM10.json`）
- **迁移**：启动时若发现旧的按场景文件，自动合成一次，然后只写新文件

### 步骤 3：拒绝要说人话

```json
{
  "ok": false,
  "error": {
    "kind": "port_busy",
    "message": "COM10 正被「定时测试」的定时发送占用（已 12.3 秒）",
    "hint": ["等它结束（约 0.5 秒/次）", "或先关掉那次定时发送", "或改用另一个口"]
  }
}
```

## 四、明确不做的（划界，防止扩散）

- ❌ **不做"多口并行写"的调度器**（比如按优先级排队）——现在没这个需求
- ❌ **不改 Transport 抽象**（L2/L3 才动）
- ❌ **不做"自动抢锁"**：默认等待，超过 2 秒就拒绝并说明，不替用户做决定
- ❌ 不碰前端布局与样式（那是 B 系列）

## 五、风险

| 风险 | 应对 |
|---|---|
| 跨进程锁在 Windows 上不稳（`msvcrt.locking` 只能锁整个文件） | 先做进程内锁 + 网页实例注册表；跨进程仅覆盖"工具转发"这一条路径 |
| 迁移状态文件时丢用户设置 | 迁移前整目录备份成 `state.bak-<时间>`，并在自检里加"迁移后每场景字段齐全" |
| 定时精度受影响 | 锁只覆盖"写入的那几毫秒"，不覆盖等待回显的 200ms |
| 自检大面积失败 | 先加一个 `selfcheck_portlock2.py`（新旧对照），过一天再删旧断言 |
