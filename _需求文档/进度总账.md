`D <ms>` 拖慢 / `N <n>` 截断回复 / `J <n>` 塞垃圾 / `S <n>` 长突发 / `B` 二进制帧。
**验证过它能逼出插件的错误路径**：`D 500` 超过场景的 `wait_first_byte_ms=300`，
插件正确报 `no_response`，并带出了场景专属提示（`no_response_hint`）。

**三个坑（都已写进注释/代码）**：
- **`0 Error(s)` 不代表没问题**：`STC8G_H_Delay.c` 的 `delay_ms()` 定义被注释掉了，
  只有声明。链接器报 `WARNING L1: UNRESOLVED EXTERNAL` 但照样生成 hex，
  运行到就跳地址 0 = **MCU 莫名复位**。`flash.py` 已加硬检查（有未解析符号就拒绝烧录，实测有效）。
- **Keil 增量编译会复用旧 `.obj`**：改回正确代码后它发现 `.obj` 比 `.c` 新，跳过编译，
  把上一轮的未解析符号又链进去。已改用 `-r` 全量重编。
- **C51 保留字**：`data` 和 `bit` 是 8051 的内存类型/位类型关键字，**不能当变量名**。

**两个坑（已写进 flash.py 注释）**：
1. **不能加 `-t`**：`-t 11059200` 会让 stcgal 请求精确微调，STC8G1K08A 步进落不到这个值 →
   `Protocol error: frequency trimming unsuccessful`。芯片当前 11.054MHz，误差 0.05%，别动。
2. **CH340 与 MCU 共用 USB 时**，冷启动会把 CH340 一起断掉，句柄失效（`WriteFile failed`）。
   `flash.py` 已加 3 次自动重试。
