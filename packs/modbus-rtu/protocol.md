# Modbus RTU 从站（通用）

> **状态**：📄 Modbus 规范通用帧格式，**本机未实测**（`unverified`）
> **来源**：[Modbus RTU 参考](https://cms.media.wilo.com/cdndoc/wilo251750/3539113/wilo251750.pdf)

## 先确认是不是它

```
01 03 00 00 00 01 84 0A      ← 读从站 1 的保持寄存器 0，1 个
期望回：01 03 02 xx xx + CRC（共 7 字节）
```

不回话的三种可能：**从站地址不是 1** / **波特率不对** / **CRC 算错**（设备直接丢弃，不报错）。

## 帧格式（RTU）

```
[从站地址 1B][功能码 1B][数据 nB][CRC16 2B]
```

- **没有起始/结束字符**，靠"总线静默 ≥3.5 字符时间"分帧
- **CRC16 低位在前**
- 常用 8N1；也有 8E1（偶校验）——**校验位错也一律丢弃**

## 最常用的四个功能码

| 码 | 作用 | 请求示例（从站1） | 响应 |
|---|---|---|---|
| `03` | 读保持寄存器 | `01 03 00 00 00 02  C4 0B` | `01 03 04 d0 d1 d2 d3 CRC` |
| `04` | 读输入寄存器 | `01 04 00 00 00 02  70 0B` | 同上 |
| `06` | 写单个寄存器 | `01 06 00 05 00 64  CRC` | 原样回显 |
| `10` | 写多个寄存器 | `01 10 00 05 00 02 04 xx xx yy yy CRC` | `01 10 00 05 00 02 CRC` |

**异常响应**：功能码最高位置 1（`03` → `83`），后跟一个异常码（如 `02` 非法地址）。

## 坑

1. **CRC 必须自己算**（多项式 0xA001，初值 0xFFFF，低字节先发）。
   算错的表现是**设备一声不响**，很容易误判成"设备坏了"。
2. **寄存器地址有 0/1 偏移问题**：手册写 `40001` 是"第 1 个保持寄存器"，
   在帧里地址要填 `0x0000`。**照手册数字直接填 40001 一定失败。**
3. **RS485 要方向控制**：很多 USB-RS485 自动切换，但便宜的转换器可能需要手动。
4. **一条总线只能有一个主站**。我们的插件扮演主站，别的软件同时问会撞。

## 用我们的工具怎么玩

```
serial_send(com="COM5", command="01 03 00 00 00 01 84 0A", display="hex")
```

**注意**：要按 hex 发。发送前把界面的"显示模式"切到十六进制，
或者用工具时标明这是二进制命令（不同版本参数名不同，先 `serial_info` 看）。

## 数据怎么读

回包是 `01 03 02 00 64 CRC` → 数据是 `0x0064` = 100。
**两个字节拼起来是"高字节在前"（大端）** —— 和 CRC 相反，容易搞混。
