## 〇之前、这个场景到底是什么（先读这段，避免误解）

### ⚠️ 名字叫"蓝牙AT"，但实际是两件事混在一起

| 用途 | 发什么 | 说明 |
|---|---|---|
| **配置 HC-05 模块** | `AT+xxx` 系列 | 改波特率、角色、名字、绑定地址 |
| **控制底盘** | `A` / `X` / `W` / `P` | 让车启动、设速度、查状态 |

**同一个串口，但发的东西完全不同。** 见命令就发，别搞混。

### ⚠️ 必须插 CH340，不能用电脑自带蓝牙

```
电脑 USB ─→ CH340（USB转串口）─→ 主机HC-05 ╎无线╎ 从机HC-05 ─→ 底盘板
```

- **电脑系统蓝牙不能直连 HC-05**：那是经典蓝牙 SPP 协议，Windows 上配对麻烦且不稳定
- **CH340 是必经之路**：把 USB 转成串口，HC-05 才能收发
- 少任何一环都不通：CH340、主机、从机、供电，四样缺一不可

### ⚠️ 本文件只对"这个型号"有效

本记录针对 **HC-05 V2.3_le（兼容版）**。其他型号指令不同：

| 型号 | AT 波特率 | 差异 |
|---|---|---|
| 原版 HC-05 | 38400（固定） | 支持完整指令集（含 `AT+PSWD`、`AT+INQ`） |
| HC-06 | 9600 | 只有 4 条命令，无从机模式 |
| JDY-31 | 9600 | 指令集完全不同 |
| BLE 模块（HM-10） | 9600 | 不支持经典蓝牙 SPP |

**换模块必须重新实测**，见文末"新模块接入流程"。

## 一、最终可用配置（已固化在模块里）

| 模块 | 地址 | 角色 | 波特率 | CMODE |
|---|---|---|---|---|
| 主机（插电脑） | `XX:XX:XX:XX:XX:01` | 1 主机 | 115200 | **1（任意地址）** |
| 从机（装车上） | `XX:XX:XX:XX:XX:02` | 0 从机 | 115200 | — |

### ⚠️ 关键经验：CMODE 必须是 1
- `CMODE=0`（固定地址 + BIND）→ 主机**不主动发起连接**，永远卡在 `PAIRABLE`
- `CMODE=1`（任意地址）→ 主机自动扫描并连接，**成功**
- 配完必须 `AT+RESET` 并**释放串口**（关闭串口），让它自己连，别一直占着口发 AT

## 二、AT 命令实测结果

| 命令 | 结果 |
|---|---|
| `AT` | OK |
| `AT+VERSION?` | +VERSION:hc05V2.3_le OK |
| `AT+ROLE?` / `AT+ROLE=0/1` | OK |
| `AT+CMODE?` / `AT+CMODE=0/1` | OK（**用 1**） |
| `AT+BIND=...` | OK（CMODE=1 时非必需） |
| `AT+UART?` / `AT+UART=115200,0,0` | OK（改后 AT 端口也跟着变） |
| `AT+ADDR?` | OK |
| `AT+STATE?` | PAIRABLE / CONNECTING / DISCONNECTED |
| `AT+RESET` | OK（重启生效） |
| `AT+ORGL` | OK（**恢复出厂：波特率回 38400、角色回从机**） |
| `AT+PSWD=xxx` | **FAIL（密码不可改）** |
| `AT+INIT` / `AT+INQ` / `AT+LINK` / `AT+PAIR` / `AT+CONN` | 无响应（不支持） |

### 重要陷阱
- **AT+ORGL 会把波特率重置为 38400、角色重置为从机**，别乱发
- 改完 `AT+UART` 后，**AT 命令的波特率也跟着变**，要跟着换
- 链路通了之后，AT 命令会被当数据转发给底盘，底盘回 `ERR STATE`（这是正常的）

## 三、底盘命令集（gcSTM32 / 01_Car_Chassis，115200 8N1）

```
A                       启动 IDLE -> RUNNING          → OK RUNNING
X                       停止 → IDLE，清空目标          → OK IDLE
R                       清故障（FAULT 只能靠它）       → OK RESET
P                       打印四路状态
E                       打印编码器原始/累计/速度
Z                       编码器清零（仅 IDLE）
S<ch> <cps>             单路目标速度，ch=1..4，count/s
W <s1> <s2> <s3> <s4>   一次设四路                   → OK 4 TARGETS
M<ch> <pwm>             开环PWM测试 -1000..1000（仅 IDLE）
G<ch> <kp> <ki> <kd>    在线改 PID
T <ms>                  周期数据流，T 0 停
H / ?                   帮助
```

### 实测行为（2026-11-04）
- `A` → `OK RUNNING`，`P` → `STATE RUNNING` ✅
- `W 1000 1000 1000 1000` → `OK 4 TARGETS`，但**未接电机立即报**
  `[FAULT] stall mask=15  send R to reset` → `STATE FAULT`
  - `mask=15` = 四路全堵转，说明堵转保护正常工作
  - **接上电机才能正常跑**，桌面测试要架空轮子
- 故障后必须发 `R` 清除，或断电重启

### 回包节奏（2026-11-04 插件化时实测）
- 命令**写下去约 0.5 s 才有第一个字节**，一次回复还会分几段吐出（`P` 共 97 字节）
- 所以读回显不能用固定 sleep：bridge.py 改成**先等首字节（默认 1500 ms）→ 再等线路安静 200 ms**
- 单条 `P` 往返约 1.1 s；慢设备可在场景 config.json 里调 `wait_first_byte_ms` / `quiet_ms`
- 同一波特率下 AT 模式下回 `OK` 很快，数据模式下走底盘才会慢，两种都覆盖得住

## 七、排查记录（踩过的坑）

1. 主机一直 `PAIRABLE` 连不上 → **CMODE 改 1**，RESET 后**释放串口**等待
2. 一直发 AT 会占用模块 → 配好后**必须关闭串口**让它自己连
3. 波特率不匹配 → 底盘 115200，模块也必须 115200
4. 手机只搜到 1 个 HC-05 且插拔从机跟随变化 → 说明从机正常广播，问题在主机侧

### ⚠️ 无回显时，先发 `AT` 判模式（2026-11-05 实测）

底盘命令（`P`/`H`/`R`）全部 0 字节时，**不要一上来就查波特率和接线**，按这个顺序：

| 步骤 | 操作 | 判读 |
|---|---|---|
| 1 | 发 `AT` | 回 `OK` → **主机卡在 AT 模式**，没进透传 |
| 2 | 发 `AT+RESET` | 回 `OK` |
| 3 | **关闭串口**，等 **20 秒** | 让它自己连从机，别一直占着口 |
| 4 | 发 `AT+STATE?` | `CONNECTED` = 通了；`CONNECTING` = 从机没上线 |

补充判读：
- 发 `AT` 回 `ERR STATE` → `AT` 已经被**转发给底盘**，链路其实是通的，直接发底盘命令
  （这是本档案第二节记过的正常现象）
- 发 `AT` 完全没反应 → 才轮到查波特率/接线/供电
- `AT+STATE?` 一直 `CONNECTING` → 从机没电、不在范围，或底盘没上电（换硬件查，别改代码）

这三步已写进场景配置的 `no_response_hint`，插件"无回显"时会直接提示出来。

## 九、⚠️ 高频故障：无回显但设备已上电（必读）

### 症状

```
- 串口能打开（不报"被占用"）
- 设备已上电、指示灯正常
- 但发 P / H 等底盘命令，完全无回显
- 换个波特率也没用
```

### 根本原因

**主机 HC-05 卡在 AT 模式，没有连上从机。**

```
主机在 AT 模式 → 只做本地应答（AT 回 OK）→ 不转发数据 → 底盘收不到命令
```

### 三步判断（一分钟）

```
1. 发 AT
   回 OK  → 说明模块在 AT 模式（正常数据模式下 AT 会被当数据转发，底盘回 ERR）
   无回显 → 不在 AT 模式，问题在别处

2. 发 AT+STATE?
   回 +STATE:CONNECTING  → 正在尝试连接但没连上 ❌
   回 +STATE:CONNECTED   → 已连接 ✅
   回 +STATE:PAIRABLE    → 等待配对

3. 查配置是否对
   AT+ROLE?   → 应为 1（主机）
   AT+CMODE?  → 应为 1（任意地址模式）
   AT+UART?   → 应为 115200
```

### 解决办法（实测有效）

```
1. 发 AT+RESET
2. 立即关闭串口（释放句柄）
3. 等 20 秒，期间不要碰串口
4. 重新打开，发 AT+STATE? 确认变 CONNECTED
5. 发 P 测试
```

**关键点：发完 RESET 必须释放串口**。一直占着串口发 AT，模块不会去建立蓝牙连接。

### 为什么会出现这个问题

调试模块配置时（发 `AT+ROLE`、`AT+BIND` 等），模块处于 AT 模式。**配置完成后如果一直占着串口，模块就无法切换到数据模式去连接从机。**

所以每次配置完，都要执行一次"RESET + 释放串口"。

### 给 AI 的提示

**遇到"无回显"报错时，不要只查波特率和接线，先按上面三步判断是不是卡在 AT 模式。**

这条比"检查设备是否上电"更常见——因为设备明明上电了，但模块在 AT 模式就是不转发。

```

**规律：`?` 查询类全通，写配置类和动作类全失败。**

### 灯态对照（一眼判断，最有用）

| 主机 HC-05 灯 | 含义 |
|---|---|
| **慢闪（约 2 秒一次）** | **卡在 AT 模式**，没进透传 |
| 快闪（约 0.2 秒一次） | 数据模式，正在尝试连接从机 |
| 双闪 / 常亮 | 已连接 |

| 从机 HC-05 灯 | 含义 |
|---|---|
| **快闪** | 在等配对，**没有人连它** |
| 常亮 | 已被连上 |

> **主机慢闪 + 从机快闪 = 主机在 AT 模式自娱自乐，从机在等一个永远不来的连接。**
> 这个组合基本可以确诊，不用再查配置。

### 根本原因

模块被**锁在 AT 模式**，且 `CONNECTING` 状态机占着蓝牙栈，导致：
- 查询类命令走的是本地寄存器，照常应答
- 写配置 / 发起连接要动蓝牙栈，被 CONNECTING 占着 → `FAIL` 或直接吞掉

**这不是配置错误**。`ROLE=1`、`CMODE=1`、`UART=115200` 都对，`BIND` 地址也在。

### 为什么 `AT+RESET` 这次没用

§九 的 RESET 办法有个前提：**模块还愿意进数据模式**。
如果它已经卡死在 `CONNECTING` 循环里，`AT+RESET` 只会软重启回同一个状态，还是 `CONNECTING`。

### 解决办法（按顺序试，从轻到重）

```
1. 发 AT+RESET，然后【立刻关闭串口】，等 20~30 秒
   （重点是"关串口"，不关的话模块没机会切模式）

2. 还不行 → 物理断电重上电
   拔掉主机 HC-05 的 VCC，等 5 秒再插回去
   ★ 这一步比 AT+RESET 可靠得多，因为能清掉 CONNECTING 状态机

3. 还不行 → 检查从机侧
   - 从机通电了吗（灯亮不亮）
   - 从机快闪 = 在等配对，说明它自己是好的
   - 从机常亮 = 已经被别的设备（比如手机）连走了，先断开

4. 还不行 → 清绑定重配
   AT+BIND=0000:00:00:00:00:00   （清空绑定）
   AT+CMODE=1                     （任意地址模式）
   然后重复第 1 步
```

### ✅ 本次实测结果（2026-11-05 22:12）

**物理断电重上电 = 有效，一次搞定。** 详细过程：

```
重插 USB 后立刻测：
  AT          → OK RUNNING   ← ★ 注意！这不是模块回的 OK，是【底盘固件】回的
  AT+STATE?   → ERR STATE    ← 底盘不认识这条命令，说明数据已透传到底盘

再测：
  P           → STATE RUNNING + 4 路通道状态   ✅ 完全正常
  X           → OK IDLE
  P           → STATE IDLE + 4 路通道状态      ✅
```

**重插后不用再按按键，也不用再发任何 AT 配置命令。**

### ★ 一个极易误判的坑：`AT` 回 `OK RUNNING` 不是模块的应答

透传模式建立后，`AT` 会被**当普通数据转发给底盘**，底盘不认识 `AT`，
但它有模糊匹配 —— **只认第一个字母**，`A` = 启动，所以回 `OK RUNNING`。

| 你发 | 模块在 AT 模式时回 | 已透传到底盘时回 |
|---|---|---|
| `AT` | `OK` | **`OK RUNNING`** ← 底盘把 A 当启动命令了 |
| `AT+STATE?` | `+STATE:CONNECTING OK` | **`ERR STATE`** ← 底盘不认识 |

**所以判断"到底通没通"，别看 `AT` 回什么，看它回的是不是 `OK RUNNING` 或多一个词。**
`AT` 回 `OK` = 还在 AT 模式；`AT` 回 `OK RUNNING` = 已经通了（底盘执行的）。

### 重插后仍然"慢闪"怎么办

本次实测：**重插后灯还会慢闪一小会儿，但通信已经正常了。**
灯态有延迟，**以实际收发为准，不要以灯为准**。

先发 `P`：
- 回 `STATE ...` + 4 路通道 → **通了，灯慢闪不用管**
- 无回显 → 才需要按上面 1~4 步继续排查

### 关键判断：什么时候该怀疑"从机没上电"

`AT+RNAME?<从机地址>` 返回 `FAIL`，有两种可能：
- 从机不在范围内 / 没上电
- 主机自己被 CONNECTING 卡住，查不了

**区分方法**：如果从机的灯**快闪**，说明它活着、在广播、在等配对 → 问题在主机（卡 AT 模式）。
如果从机的灯**不亮**，才是从机没电。

**2026-11-05 这次的情况**：从机快闪（活着），主机慢闪（卡 AT 模式）
→ **问题 100% 在主机，不在从机，也不在配置。**

### 给 AI 的提示

1. **先问灯态，再查 AT**。灯态能省掉一半排查。
2. 看到"查询全通、写入全 FAIL"这个模式，**直接判定卡 AT 模式**，不要再逐项验证配置。
3. `AT+RESET` 不是万能的，**卡 CONNECTING 时必须物理断电**。
4. 不要因为 `AT+RNAME?` 返回 `FAIL` 就断言从机没上电——**先看从机灯**。
